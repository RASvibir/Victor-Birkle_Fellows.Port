Production-shaped ASR → NLU conditions

Same core question at a harder fidelity: when does confidence diverge from accuracy under ASR/channel noise, domain shift, and class-prior shift — and can operational signals flag that gap without ground truth at inference time?

Core question

In a production ASR → NLU intent-classification pipeline, under what measurable conditions does reported model confidence diverge from realized accuracy — and can those conditions be detected from operational signals alone (latency, audio quality proxies, utterance length, class prior shift) without privileged access to ground truth at inference time?

Narrow on purpose. Not a claim about frontier alignment. An empirical diagnostics question about a failure mode from production systems: high-confidence wrong answers under distribution shift.

Why this question

At OpenCity I cleaned multimodal training data, built regression checks for conversational models, and wrote log parsers for anomalous application state. The recurring pattern was not “the model is always wrong,” but confidence that stayed high while accuracy slipped when input conditions changed.

The pilot below shows I can close a question→result loop on a toy. It also showed that naive token corruption produces underconfidence — so the fuller study must use corruption mechanisms that can create high-confidence errors, not just destroy evidence.

Method — full study (planned)

Data & model

  • Fixed intent taxonomy (8–12 classes) on public speech/text or a held-out production-like corpus.
  • Controlled corruptions closer to production: SNR / channel noise, truncation, OOD phrases, class-prior shift.
  • Simple, reproducible baseline in Python (embeddings + linear head or small transformer) with fixed seed.

Measurements

  • Per utterance: predicted label, max softmax / calibrated confidence, true label, operational features.
  • Primary: reliability diagrams and Expected Calibration Error (ECE) stratified by operational bins — not only aggregate accuracy.
  • Secondary: which operational features best predict |confidence − correctness| on a holdout set (AUC / Brier); report what fails.

Success criteria for the writeup

  • One clear positive or negative result about when confidence stops tracking accuracy.
  • Explicit statement of what the pilot already ruled out (token dropout alone).
  • Negative results welcome and preferred over vague claims.
